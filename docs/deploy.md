# Deploy

- Cloudflare Pages project `quickeval`, connected to the GitHub repo. Every push to `main` deploys. Build command `npm run build`, output `dist`, Node version from `.node-version`. Preview deployments are off: they would share the production database and bucket.
- `wrangler.toml` is the source of truth for bindings: D1 `DB` → database `quickeval`, R2 `FILES` → bucket `quickeval-files`.
- Settings `ACCESS_TEAM_DOMAIN` and `ACCESS_AUD` are Pages secrets: `npx wrangler pages secret put <NAME> --project-name quickeval`. A new secret applies from the next deployment. `GITHUB_REPO` and the Pages secret `GITHUB_DISPATCH_TOKEN` (spec §12.6) let "Pornește evaluarea", "Reîncearcă" (one upload), "Încearcă din nou", "Folosește oricum" (the exercise list), a new barem during evaluation, the first request after a scheduled evaluation's time, and "Pornește robotul" start the robot at once. Without them, or when GitHub refuses the request, the robot does not start, and the work waits for the robot's next run (another of these requests, or a run by hand: "The robot", below). The API keeps the time of the failed request (`runner_state.start_failed_at`), also when a student's request started a scheduled evaluation. The test page of every test in "Se corectează" then tells the teacher that the robot did not start. The message goes away when a run checks in or a later request starts the robot. It does not show while a run works. The token needs Contents: Read and write on the repository. When GitHub refuses the request, `npx wrangler pages deployment tail --project-name quickeval` shows its HTTP status.
- A new migration runs on the live database before the code that needs it: `npx wrangler d1 migrations apply quickeval --remote`. A new binding's resource (a bucket, a database) exists before the code that binds it reaches `main`.
- Cloudflare Access ("QuickEval admin") protects only `/admin` and `/api/admin`. Student pages (`/u`, `/api/u`) and the robot (`/api/runner`) must stay outside it.
- CI (`.github/workflows/ci.yml`) runs the typecheck, the tests, and the build on every push and pull request.

## The robot

- The robot (`.github/workflows/evaluate.yml`) runs on "evaluate-now" and by hand (GitHub, Actions, evaluate, Run workflow, or `gh workflow run evaluate.yml`). Its 10-minute schedule does not fire today (`docs/superpowers/plans/plan-3b-followups.md`, "From the go-live"). When a run stops before its work is done, the test page shows "Pornește robotul" after 30 minutes without a check, and that button starts a new run. A run by hand is the fallback only, for example when the site cannot reach GitHub. Its GitHub settings (Settings, Secrets and variables, Actions): the variable `QUICKEVAL_URL` (`https://quickeval.pages.dev`), the secrets `QUICKEVAL_RUNNER_KEY` (Setări, "Fă o cheie nouă") and `CLAUDE_CODE_OAUTH_TOKEN` (`claude setup-token`; it lasts a year: renew it before), and optional variables `QE_MODEL` (default `opus`) and `QE_EFFORT` (default `high`). Without the variable or the key, every run finds no work and passes.
- A robot run fails, and GitHub sends an email, when the API refuses the key or cannot be reached, when `CLAUDE_CODE_OAUTH_TOKEN` is missing or Claude refuses it (Setări then says "tokenul Claude nu mai merge"), when three tasks in a row fail (a wrong `QE_MODEL`, an outage), or when Claude Code or pandoc is missing. A usage limit is no failure: a later run goes on.
- Claude Code is pinned in `evaluate.yml`. To update it: install the new version on this PC, run `npm run try:skill` with it, then change the pin. A model that needs a newer Claude Code makes every task fail: the run stops after three failures in a row.
- The print PDF (the test with the student-upload QR code) is made in a Docker image built from `runner/print/Dockerfile`. Migration 0014 (`npx wrangler d1 migrations apply quickeval --remote`) runs on the live database before the merge. The first robot run with a print job builds the image (a few minutes); later runs reuse it.
- LibreOffice is pinned in `runner/print/Dockerfile` (version and SHA-256). To update it: set the new version and its SHA-256, run `$env:QE_PRINT_IMAGE_TESTS='1'; npx vitest run runner/print/container.test.ts`, and look at the PDFs of two real Word tests before the merge.

## Operations

- **The Claude token** (`CLAUDE_CODE_OAUTH_TOKEN`) lasts one year. Renew it before it ends: `claude setup-token` on this PC, then GitHub, Settings, Secrets and variables, Actions, and replace the secret. Setări shows the date of the last successful grading, and says "tokenul Claude nu mai merge" when Claude refuses it. Write the renewal date in your calendar when you set it.
- **The class analysis** is one more Claude call for each test, after its gradings, in the same run. A test stays in "Se corectează" until it is written (or has failed three times). If a usage limit stops a run, "Pornește robotul" on the test page continues it. A test graded before analyses existed shows "Fă analiza clasei" in its report.
- **R2 and the school years**: each September, look at the R2 usage in the Cloudflare dashboard (Storage, R2, `quickeval-files`). Files are kept under `t/<teacherId>/<schoolYear>/<testCode>/`. To free space for an old school year, open each of its tests in the app and use "Șterge testul": it deletes the files and the rows. Do not delete objects from the dashboard: the database would still list them.
- **D1 history**: Time Travel keeps 7 days on the free plan. To read the state of an earlier moment: `npx wrangler d1 time-travel info quickeval`; to go back to it: `npx wrangler d1 time-travel restore quickeval --timestamp <time>` (this replaces the live data: do it only to undo a mistake, and tell the teacher first).
- **A new migration** runs on the live database before the code that needs it reaches `main` (see above). Plan 4b adds none.
- **PDFs and the CSV** are made in the teacher's browser: nothing of them is stored on the server.
