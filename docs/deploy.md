# Deploy

- Cloudflare Pages project `quickeval`, connected to the GitHub repo. Every push to `main` deploys. Build command `npm run build`, output `dist`, Node version from `.node-version`. Preview deployments are off: they would share the production database and bucket.
- `wrangler.toml` is the source of truth for bindings: D1 `DB` → database `quickeval`, R2 `FILES` → bucket `quickeval-files`.
- Pages secrets are set with `npx wrangler pages secret put <NAME> --project-name quickeval`. A new secret applies from the next deployment. `GITHUB_REPO` and the Pages secret `GITHUB_DISPATCH_TOKEN` (spec §12.6) let "Pornește evaluarea", "Reîncearcă" (one upload), "Încearcă din nou", "Folosește oricum" (the exercise list), a new barem during evaluation, the first request after a scheduled evaluation's time, "Pornește robotul", and, for the print PDF, "Începe testul", "Redeschide încărcarea", a new test file on an open test, and "Încearcă din nou" on the print PDF start the robot at once. Without them, or when GitHub refuses the request, the robot does not start, and the work waits for the robot's next run (another of these requests, or a run by hand: "The robot", below). The API keeps the time of the failed request (`runner_state.start_failed_at`), also when a student's request started a scheduled evaluation. The test page of every test in "Se corectează", and of an open test whose print PDF waits, then tells the teacher that the robot did not start. The message goes away when a run checks in or a later request starts the robot. It does not show while a run works. The token needs Contents: Read and write on the repository. When GitHub refuses the request, `npx wrangler pages deployment tail --project-name quickeval` shows its HTTP status.
- A new migration runs on the live database before the code that needs it: `npx wrangler d1 migrations apply quickeval --remote`. A new binding's resource (a bucket, a database) exists before the code that binds it reaches `main`.
- Teachers log in with email and password (see "Accounts" below). Cloudflare Access is no longer used: its free plan stops at 50 users, and every new teacher would have to be added to its policy by hand. Student pages (`/u`, `/api/u`) and the robot (`/api/runner`) need no login.
- CI (`.github/workflows/ci.yml`) runs the typecheck, the tests, and the build on every push and pull request.

## Accounts

- A teacher logs in at `/admin/` with email and password. The login is a cookie (`qe_session`, 30 days, only its SHA-256 is stored in `sessions`). Passwords are PBKDF2-SHA-256 hashes (`server/passwords.ts`). Ten wrong passwords in a row lock the account for 15 minutes, but not for a browser that logged in to it before (the `qe_device` cookie, one year): someone guessing cannot lock the teacher out. A wrong password, an unknown email and a locked account get the same answer, and signing up with an email that has an account answers like any sign-up and changes nothing, so neither form tells which emails have an account.
- Roles: the administrators (`teachers.role = 'admin'`: plesalaura@yahoo.com and mg1497_miron@yahoo.com, set by migration 0015) open Setări, approve accounts, and change the robot's settings. Every other teacher sees Teste, Clase and Contul meu.
- "Vreau cont nou" on the login page makes a pending demo account. Both administrators get an email (when the email settings below exist) and approve or refuse it on Setări, "Conturi". Setări lists the accounts that wait even without email. At most 50 accounts wait at the same time, at most 3 from one IP in a day, and an account that waits 30 days is deleted. A name holds only letters, spaces, dots, apostrophes and hyphens, so a sign-up cannot put a link in the administrators' email.
- A demo account sends at most 5 tests to evaluation (`DEMO_TEST_LIMIT` in `shared/accounts.ts`); a test counts once, also after a reopen, a regrade or a delete. Everything else works as for any teacher. An administrator makes it complete on Setări ("Fă cont complet").
- A teacher who forgot the password: an administrator uses "Parolă nouă" on Setări and sends the teacher the password it shows; the teacher also gets an email that an administrator changed it. An administrator's password never changes on Setări (an administrator could then log in as the other): an administrator who forgot theirs runs `npm run set-password -- <email>` on this PC (it writes to the live database with wrangler).
- **Emails** (optional): a free Brevo account (brevo.com, 300 emails a day, no own domain needed). In Brevo: verify a sender address (Senders, Domains & Dedicated IPs, Senders), then make an API key (SMTP & API, API Keys). Then `npx wrangler pages secret put BREVO_API_KEY --project-name quickeval` and `npx wrangler pages secret put EMAIL_FROM --project-name quickeval` (the verified sender). Brevo sends mail from a Gmail or Yahoo sender through its own domain, so the email may come from an address like `...@...brevosend.com`; look in Spam the first time. Without the two secrets, nothing is sent and the app works the same. A refused email shows in `npx wrangler pages deployment tail --project-name quickeval` as "Brevo refused the email: HTTP <status>".
- **Go-live of the accounts**: in this order.
  1. `npx wrangler d1 migrations apply quickeval --remote` (migration 0015) before the merge.
  1b. Check the administrators: `npx wrangler d1 execute quickeval --remote --command "SELECT id, email, role FROM teachers"`. Migration 0015 makes `plesalaura@yahoo.com` and `mg1497_miron@yahoo.com` administrators; when neither has a row, the first teacher stays one.
  2. Set the administrators' passwords: `npm run set-password -- plesalaura@yahoo.com` and `npm run set-password -- mg1497_miron@yahoo.com`. Each ends with "Gata: … intră acum cu parola nouă."; when it says the email has no account, that email has no row in `teachers` yet: add it first (`INSERT INTO teachers (email, name, created_at, role) VALUES ('<email>', '<name>', strftime('%Y-%m-%dT%H:%M:%fZ', 'now'), 'admin')`).
  3. Merge. Until step 4, Access still asks for its code before the login page; that is harmless.
  4. In the Cloudflare dashboard (Zero Trust, Access, Applications), delete the application "QuickEval admin", so new teachers reach the login page. Then remove the old secrets: `npx wrangler pages secret delete ACCESS_TEAM_DOMAIN --project-name quickeval` and the same for `ACCESS_AUD`.
  5. Optional: the Brevo secrets above.

- **What the code cannot stop**: every request to `/api/*` counts toward the free plan's 100 000 Function requests a day, refused or not, so a flood of requests to the login page could use them up for the day. Only Cloudflare's rate limiting stops requests before the Function, and it needs a custom domain (a zone) instead of `quickeval.pages.dev`. If that ever happens: add a domain to Cloudflare, serve the project on it, and add a rate-limiting rule for `/api/auth/*`.

## The robot

- The robot (`.github/workflows/evaluate.yml`) runs on "evaluate-now" and by hand (GitHub, Actions, evaluate, Run workflow, or `gh workflow run evaluate.yml`). Its 10-minute schedule does not fire today (`docs/superpowers/plans/plan-3b-followups.md`, "From the go-live"). When a run stops before its work is done, the test page shows "Pornește robotul" after 30 minutes without a check, and that button starts a new run. A run by hand is the fallback only, for example when the site cannot reach GitHub. Its GitHub settings (Settings, Secrets and variables, Actions): the variable `QUICKEVAL_URL` (`https://quickeval.pages.dev`), the secrets `QUICKEVAL_RUNNER_KEY` (Setări, "Fă o cheie nouă") and `CLAUDE_CODE_OAUTH_TOKEN` (`claude setup-token`; it lasts a year: renew it before), and optional variables `QE_MODEL` (default `opus`) and `QE_EFFORT` (default `high`). Without the variable or the key, every run finds no work and passes.
- A robot run fails, and GitHub sends an email, when the API refuses the key or cannot be reached, when `CLAUDE_CODE_OAUTH_TOKEN` is missing or Claude refuses it (Setări then says "tokenul Claude nu mai merge"), when three tasks in a row fail (a wrong `QE_MODEL`, an outage), when Claude Code or pandoc is missing, or when the print image cannot be built (that run makes no print PDF, counts no attempt, and exits 1; the next run tries again). A usage limit is no failure: a later run goes on.
- Claude Code is pinned in `evaluate.yml`. To update it: install the new version on this PC, run `npm run try:skill` with it, then change the pin. A model that needs a newer Claude Code makes every task fail: the run stops after three failures in a row.
- The print PDF (the test with the student-upload QR code) is made in a Docker image built from `runner/print/Dockerfile`. Every robot run that has a print job builds the image: GitHub's machines start empty and the workflow keeps no cache, so this takes about 1-2 minutes each time and needs `downloadarchive.documentfoundation.org` to answer (LibreOffice comes from there).
- **Go-live of the print PDF**: migration 0014 (`npx wrangler d1 migrations apply quickeval --remote`) runs on the live database before the merge. The tests that are open when it runs become print jobs, but nothing starts the robot for them. After the merge and the Pages deploy, start one run (`gh workflow run evaluate.yml`, or "Pornește robotul" on such a test). Then upload one Word test and one PDF test of Laura's to an open test, and look at both PDFs before anyone prints them.
- LibreOffice is pinned in `runner/print/Dockerfile` (version and SHA-256). To update it: set the new version and its SHA-256, run `$env:QE_PRINT_IMAGE_TESTS='1'; npx vitest run runner/print/container.test.ts`, and look at the PDFs of two real Word tests before the merge.

## Operations

- **The Claude token** (`CLAUDE_CODE_OAUTH_TOKEN`) lasts one year. Renew it before it ends: `claude setup-token` on this PC, then GitHub, Settings, Secrets and variables, Actions, and replace the secret. Setări shows the date of the last successful grading, and says "tokenul Claude nu mai merge" when Claude refuses it. Write the renewal date in your calendar when you set it.
- **The class analysis** is one more Claude call for each test, after its gradings, in the same run. A test stays in "Se corectează" until it is written (or has failed three times). If a usage limit stops a run, "Pornește robotul" on the test page continues it. A test graded before analyses existed shows "Fă analiza clasei" in its report.
- **R2 and the school years**: each September, look at the R2 usage in the Cloudflare dashboard (Storage, R2, `quickeval-files`). Files are kept under `t/<teacherId>/<schoolYear>/<testCode>/`. To free space for an old school year, open each of its tests in the app and use "Șterge testul": it deletes the files and the rows. Do not delete objects from the dashboard: the database would still list them.
- **D1 history**: Time Travel keeps 7 days on the free plan. To read the state of an earlier moment: `npx wrangler d1 time-travel info quickeval`; to go back to it: `npx wrangler d1 time-travel restore quickeval --timestamp <time>` (this replaces the live data: do it only to undo a mistake, and tell the teacher first).
- **A new migration** runs on the live database before the code that needs it reaches `main` (see above). The accounts add migration 0015 (see "Accounts").
- **PDFs and the CSV** are made in the teacher's browser: nothing of them is stored on the server.
