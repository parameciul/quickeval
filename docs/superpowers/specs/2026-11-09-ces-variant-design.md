# CES variant: an adapted test and its own barem

Date: 2026-11-09. Status: approved by the teacher.

## Intent

Some students have special educational needs (CES, "cerințe educaționale speciale"). For them the teacher writes an adapted version of the class test: the same contents and, usually, the same items and points, but with guided steps, blanks to fill in, a box of useful formulas, and more time. A real sample is in `D:\Projects\Test\` ("Test adaptat - Modul, parte intreaga, parte fractionara.docx" and its "- barem.docx").

Today MQGrader knows one test file and one barem per test. A CES student's paper is graded against the class barem, which does not match the adapted paper. This feature lets the teacher add one CES variant to a test, with its own barem, and keeps the CES students inside the class everywhere else.

The teacher's words: the CES student is part of the class. They get the special test with the same QR code, upload on the same test link (or the teacher uploads for them), and get their result on the same results link, with the same information as the others. For the teacher it is the same test in the class.

## Goals

- The teacher marks a student as CES in the class list.
- On a test of a class that has at least one CES student, the teacher can add an optional CES variant: its own test file, its own barem (uploaded, or generated by the robot), its own print PDF.
- All CES students of the class get the same CES variant.
- The CES variant always has its own barem. It never falls back to the class barem.
- A CES student's paper is graded by the robot against the CES test and the CES barem.
- The results, the papers table, the CSV, the averages and the class analysis include the CES papers.
- A CES variant with fewer exercises fills only the columns of the exercises it has.

## Non-goals

- More than one CES variant per test. One variant serves all CES students of the class.
- A different variant per student.
- Per-student adaptations stored in the app (diagnoses, recommendations, extra time). The adapted test file carries them.
- Writing the adapted test itself. The teacher brings the test file.
- The teacher-facing parts of the sample barem in a generated barem (see "The generated CES barem").

## Anti-goals (a failure even if it works)

- Any student page, student PDF or student-visible text that says "CES", "adaptat", or anything that sets the CES student apart from the class. Student pages already must not tell how the work is graded (`expectNoGradingWords()`); the same tests must also find no CES word.
- A CES paper graded against the class barem, silently, because the CES barem was missing or not yet checked.
- A regrade that switches a paper from one barem to the other without the teacher doing it.
- Two tests in the class for one class test.
- Names in the robot's work folder or in its answers.

## Constraints

All the rules of `AGENTS.md`, `server/AGENTS.md`, `runner/AGENTS.md` and `src/AGENTS.md` apply. The ones that bite here:

- Every check of a write is inside its own SQL statement, not a read before the write.
- Every path that makes robot work calls `startRobot`.
- Every teacher query is scoped by the teacher's id.
- The migration goes to the live database before the code that needs it reaches `main` (`docs/deploy.md`).
- At most 10 ms CPU and 15 D1 queries per request.
- User-facing text in Romanian; code and docs in English.

## The parts the teacher decided

### The CES mark

- The teacher marks a student as CES in the class list (the class page). She can remove the mark.
- The mark is on the student, not on one test.

### The CES variant on the test page

- When the class has at least one active CES student, the test page shows an optional "Varianta CES" block. When the class has none, the block is not shown, unless the test already has a CES variant (then it stays, so the teacher can see and remove it). Since the CES switch (`2026-11-09-ces-switch-and-missing-warnings-design.md`), the block holds the switch "Test separat pentru elevii cu CES", on by default; off removes the CES files and replaces "Șterge varianta CES".
- The block has: the CES test file, the CES barem (upload or "Generează baremul"), the comments for the CES barem, and the CES print PDF.
- The CES print PDF carries the same QR code and the same upload link as the class print PDF.

### Uploads and results

- CES students upload on the same test link. The teacher can upload for them, as for any student.
- They see their result on the same results link, with the same information as the others. The student PDF looks the same.

### Tables, grades and the analysis

- The teacher sees one test. Every teacher table that lists students shows a small "CES" mark next to a CES student's name, so they are easy to find. The mark is for the teacher only.
- Tables that show only the final score or grade (the results under a test, the class page with all its tests, and the like) show the CES student's score in the same column as everyone else.
- Tables that show the points per exercise (the papers table, the class report): when the CES exercise list matches the class list (the same exercise ids and the same maximum for each), the CES rows are in the same table, in the same columns. When the number of exercises or the points of any exercise differ, the CES papers go in a separate table, with the CES exercises as its columns, under the class table. "Match" is decided per test from the two exercise lists, not per paper.
- A CES barem always totals 90 + 10 points, like the class barem (teacher's choice). When the teacher drops an exercise, she moves its points to the other exercises. A generated CES barem must total 90 + 10. When the CES exercise list does not total 90 + 10 (an uploaded barem with other sums), the test page shows a warning in Romanian on the CES block; it does not block grading. The grade is still found by `gradeOf` in `shared/scoring.ts` from the variant's own maximum, which is then 100.
- The class averages of the final score or grade include the CES papers. The per-exercise averages of the class table use only the papers in that table.
- The CES papers count in the class analysis. The analysis gets an anonymous flag per paper and the CES exercise list when it differs.

## The generated CES barem

"Generează baremul" on the CES variant asks the robot for a barem that is only for grading. The teacher reads it and confirms it, the same as a generated class barem (`barem_unchecked`).

Inputs to the robot:

- the CES test file;
- the class barem and the class exercise list, when they exist, so the CES barem reuses the class exercise ids and labels, and the columns line up;
- the teacher's comments for the CES barem.

The output follows the shape of the sample's sections 3 and 4:

- the grading rules ("Reguli de notare"), as the "Precizări" of a class barem;
- the table: each item with its steps and the points of each step;
- the "Observații" lines after the table, when an item needs them.

The output leaves out the sample's sections 1 ("Ce s-a adaptat și de ce"), 2 ("Cum se administrează testul") and 5 ("Competențe evaluate"), the "confidential" line, and the student's name.

The CES grading rules come from the sample:

- 10 points "din oficiu"; any correct solution gets the full points, even if it does not follow the steps;
- a blank filled in correctly gets the points of its step, with no other written justification;
- no points are taken off for spelling, for hard-to-read writing, or for digits or signs swapped while copying, when the next calculations show that the student worked with the correct value;
- no fractions of a point; partial points by steps only, inside the limits of the barem.

The sample's "hard-to-read writing, if the student explains it orally" cannot be done by the robot. The robot writes it as: hard-to-read writing is not penalized; when the robot cannot read an answer, it marks the item for the teacher to check (the existing low-confidence review path).

The class rule "a correct final result without the justifications gets at most half of the points" does not go into the CES barem: in a guided test the blanks are the justifications.

The skill gets a second reference, next to `references/barem-example.md`: the sample CES test and barem, with the student's name, the date and the class removed, and only sections 3 and 4 of the barem kept. `references/barem-writing.md` gets a section "Barem pentru varianta CES" with the rules above.

An uploaded CES barem is always active, as an uploaded class barem is. It may be the teacher's full document, with the teacher parts; the robot grades from it as it is.

## Rules the builder must keep

### Which variant a paper uses

- A paper's variant is fixed when the paper first goes to grading: a CES paper if the student is marked CES and the test has a CES variant at that moment, a class paper otherwise. It is written on the submission.
- A regrade and a retry keep the paper's variant. A reset deletes the paper, so the student's next paper gets its variant when it goes to grading. Removing or adding the CES mark later does not change papers that already went to grading; it changes only papers that have not yet gone.
- A CES student on a test with no CES variant is graded as a class paper, with the class test and barem. (Teacher's choice: the variant is optional.)
- The review page, the paper's page and the per-paper PDF show the test and barem of the paper's own variant.

### What the variant has of its own

Today each of these is one per test. The CES variant needs its own copy of each:

- the test file (key, name, type);
- the barem file (key, name, type) and the barem comments (`barem_notes`);
- the barem request and its attempts (`barem_request`, `barem_request_attempts`) and `barem_unchecked`;
- the exercise list and its status, message and attempts (`exercise_list_*`); grading a CES paper reads the CES `exercises.json`;
- the print PDF and its status and attempts (`print_*`);
- a files version, bumped on every change of a CES file, so the robot drops CES work it already holds. A change to a class file does not touch CES work in progress, and the reverse.

### The gates

- The class barem gates the test as today (`BAREM_ACTIVE`). The CES barem gates only the CES papers (teacher's choice). When the CES variant has no active barem (none yet, generating, or not confirmed) or no usable CES exercise list, the test still starts: the class papers go to the robot, and the CES papers wait, the same way demo-unselected uploads wait. They go when the CES barem becomes active (confirm, upload), through `startRobot`. The test page tells the teacher in Romanian that the CES papers wait for the CES barem.
- Every path that now sends papers (evaluation start, `DUE`, regrade, retry, the claim paths in `server/db/lifecycle.ts`) applies this per paper, inside its SQL.
- `NEEDS_PRINT` gets a CES twin: a draft or open test with its upload link, a CES test file and no CES print PDF.
- Every path that makes CES work (barem generation, exercise list, print, grading) calls `startRobot`.
- The demo limits count CES papers like any paper (`DEMO_PAPER_LIMIT`, `WITHIN_PAPER_LIMIT`, `papersToSend`). A CES variant is not a second test for `ONLY_TEST`.
- `askForAnalysis` and `askAnalysisAfterCheck` wait for the CES papers too, as for any paper.

### Columns and points

- The CES exercise list reuses the class exercise ids and labels wherever an item is the same item. This holds for an uploaded CES barem too: the CES exercise-list job gets the class exercise list as an input. The CES list job runs after the class list exists (builder's call).
- When the lists match, the columns are the class columns. When they differ, the separate CES table takes its columns from the CES list (see "Tables, grades and the analysis").
- `askForAnalysis` waits for the waiting CES papers too.

### Removing or replacing the variant (builder's call, checked by the teacher)

- The teacher can replace the CES files at any time, the same as the class files (the CES files version is bumped).
- The teacher can remove the CES variant only while no CES paper has gone to grading, checked in the SQL of the removal (like Stop test).
- Marking or unmarking a student never changes a paper that already went to grading.

### Uploads and the CSV (builder's call, checked by the teacher)

- The upload pages do not change. The variant is decided only when a paper goes to grading.
- The CSV has no CES column: it is often shared, and CES status is private. It holds the CES papers' scores like any others; with a separate CES table, the CSV puts the CES rows in their own block with their own exercise headers.

### The robot

- `class-results.json` gets an anonymous `variant` field per paper ("class" or "ces").
- The work folder still has no names.
- Grading a CES paper: `test/` holds the CES test, `barem/` the CES barem, `exercises.json` the CES list.
