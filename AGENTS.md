# AGENTS.md

MQGrader (formerly QuickEval): a web app that helps Laura Miron (math teacher, Liceul William Shakespeare, Timișoara) collect and grade her students' math tests. The product name is MQGrader; the code, the URLs, the secrets, the database and the repository keep the old name quickeval. Every page is in Romanian (the default) and in English, which the reader chooses with the RO/EN button. Code, comments, and docs are in English.

- Design: `docs/superpowers/specs/2026-10-06-quickeval-design.md`. The English version: `docs/superpowers/specs/2026-11-20-english-version-design.md`. Plans: `docs/superpowers/plans/`. The redesign of the look and layout (light by default, the 80 px bar, the six stages, the new landing page) is in `docs/superpowers/specs/2026-11-04-mqgrader-redesign-design.md`; it is built in phases.
- Live: https://quickeval.pages.dev/. Brand source: the "Matematică cu Laura Miron" site (`D:\Projects\Website`, https://lauramiron.mqgrader.ro/; the old https://lauramiron.pages.dev/ redirects there).
- More instructions: `src/AGENTS.md`, `server/AGENTS.md`, `runner/AGENTS.md` (read the one for the area you change), and `docs/deploy.md` (deploy, secrets, the robot's GitHub settings).

## Structure

- `en/`: the English copies of the six public pages (`en/index.html`, `en/guide/`, `en/grading/`, `en/questions/`, `en/about/`, `en/pricing/`).
- `index.html` (landing page), `teacher/index.html` (teacher app, `/teacher/`), `u/index.html` (student app, `/u/<token>`), `try/index.html` (a Quick Try's page, `/try/<token>`), and the five pages that answer a search: `guide/` (`/guide/`, how to use MQGrader, the six stages of a test), `grading/` (`/grading/`, how to grade a test by barem: a good barem, the time it takes, what can be automated), `questions/` (`/questions/`, the landing page's and the grading page's questions on a page of their own, in the order of a test's stages and the account last: the `questions-list` part in `src/landing/partials.ts`, made from the same items as the landing page's `faq-list`; the FAQPage data stays on the landing and grading pages), `about/` (`/about/`, who builds MQGrader), `pricing/` (`/pricing/`, what a test costs).
- `src/`: the two React apps (`admin/`, `upload/`), the landing page's stylesheet, theme button, Quick Try form and the content pages' stylesheet (`landing/`, no React), shared UI (`ui/`), test helpers (`test/`).
- `functions/api/[[route]].ts`: the Cloudflare Pages entry for `/api/*`; it serves the Hono app from `server/app.ts`.
- `server/`: the API (routes, D1 queries, auth, R2 files, secrets, emails).
- `shared/`: code for the API, the browser, and the robot: zod request schemas and response types (`api.ts`), roles and the demo paper limit (`accounts.ts`), school year, class and student names, ids, test codes (`tests.ts`), file rules and R2 keys (`files.ts`), the robot's output contracts and their JSON Schemas (`schemas.ts`), points and grades (`scoring.ts`), robot API bodies (`runner.ts`), the search fold that ignores case and diacritics (`search.ts`), the subjects the robot grades and the message for one it does not (`subjects.ts`).
- Payments with Stripe Checkout: `docs/payments.md`.
- Visit counts: a self-hosted Rybbit at https://stats.mqgrader.ro, loaded by the six public pages, the student pages and the Quick Try pages (their tokens masked, no referrer), and by the teacher app on its login screen only (`src/ui/visits.ts`, `docs/analytics.md`).
- `migrations/`: D1 SQL migrations, numbered. One statement per `;` at a line end (the test helper splits on that), and no `;` inside strings.
- `public/`: copied as-is into `dist/` (`_routes.json`: only `/api/*` runs Functions; `_redirects`, `_headers`, `lang.js`, `theme.js`, `favicon.svg`, `robots.txt`, `sitemap.xml`, `llms.txt`, `og-image.png`, `og-guide.png`, `og-grading.png`, `og-about.png`, `og-pricing.png`, `logo.png`, `app-teste.png`, `app-graded-paper-v2.png`, `screens/` (the public pages' app screenshots, WebP), and the IndexNow key, a file named with 32 hex characters). Only the six public pages are indexed: the landing page (https://mqgrader.ro/, the canonical address) and `/guide/`, `/grading/`, `/questions/`, `/about/`, `/pricing/` (their Romanian addresses until 2026-11-17, `/ghid/`, `/barem/`, `/despre/`, `/preturi/`, and `/marking-scheme/` until 2026-11-21, answer with a 301 in `_redirects`: keep those rules). Each has its own canonical, Open Graph tags and JSON-LD in its `index.html`, and the five content pages link to each other in their footer; `_headers` gives `/teacher`, `/teacher/*`, `/u/*`, `/try/*` and the whole old host quickeval.pages.dev `X-Robots-Tag: noindex` (the API sets its own, in `server/app.ts`), and `robots.txt` closes `/u/`, `/try/` and `/api/` but leaves `/teacher/` crawlable so its noindex is seen. SEO work targets mqgrader.ro only, never quickeval.pages.dev. `_redirects` must use the directory form `/teacher/* /teacher/ 200` and `/u/* /u/ 200`: Wrangler refuses `/teacher/* /teacher/index.html 200` as a redirect loop. The old `/admin` paths redirect to `/teacher` with 301.
- `scripts/`: `seed-local.sql` (the local teacher, an administrator), `setPassword.ts` (`npm run set-password -- <email> [--local]`: an account's password straight in D1), `smoke.mjs` (checks a running local server, with one full upload graded by a pretend robot), `indexnow.mjs` (`npm run indexnow`: announces the sitemap's addresses to IndexNow, for Bing and the engines that share it).
- `runner/`: the grading robot (spec §12), run by `.github/workflows/evaluate.yml`. `.claude/skills/evaluate-test/`: its grading skill (spec §13).
- `runner/print/`: the print container (pinned LibreOffice and the QR stamp) that makes the test's print PDF.
- `.claude/skills/seo/` and `.claude/skills/seo-*`: the vendored Claude SEO skill (MIT, upstream `AgriciDaniel/claude-seo` v2.5.0), loaded by both Claude Code and OpenCode. Its runtime paths were rewritten to `python .claude/skills/seo/scripts/runtime.py`; leave the rest as upstream. `.opencode/agents/seo-*.md` and `.opencode/commands/seo.md` are its OpenCode counterparts. For Claude Code it is off by default, to keep the sessions' context small: its agents live in `.claude/seo-agents/` (upstream puts them in `.claude/agents/`: put an update's agents in `.claude/seo-agents/`), and `pwsh -File scripts\seo-toggle.ps1 on|off` turns the skills (in the main checkout's `.claude/settings.local.json`) and this checkout's agents on or off; start a new session after it. Its Python environment and Chromium are local only (gitignored) and come from `python .claude/skills/seo/scripts/runtime.py setup`.

## Commands

- `npm test`: all tests (Vitest projects "web", "shared", "server", "d1", "runner"; about 50 s on the development PC). Run less while you work: `npm run test:web`, `test:server`, `test:runner`, `test:d1` (the tests on the real local D1, see `server/AGENTS.md`), `test:changed` (files changed since the last commit and what imports them), `npm run test:related -- <file>`, `npm run test:watch`. Run the whole suite before a push. `npm run test:times`: the whole suite, then the time by area and the slowest files and tests; it fails when a file takes more than 20 s, setup included (`TEST_FILE_BUDGET_SECONDS`): split such a file by its `describe` blocks. `npm run typecheck`: one strict config for everything. `npm run build`: typecheck, then the Vite build into `dist/`.
- `npm run db:local`: apply the migrations to the local D1 and add the local teacher.
- `npm run dev:api` and `npm run dev:web` (two terminals): hot reload at http://localhost:5173/teacher/. A started test's student page is at `http://localhost:5173/u/<token>`.
- `npm run db:local`, then `npm run preview`, then `npm run smoke` in a second terminal: the production build on http://127.0.0.1:8788 and its smoke test. Each smoke run leaves one class with one student in the local database, and makes a new local robot key.
- `npm run try:skill`: try the grading skill on this PC (see `runner/AGENTS.md`). `npm run compare:skills`: the old grading skill against the new one on real math tests of the live site (see `runner/AGENTS.md`).
- Claude Code preview servers (`.claude/launch.json`): `api` (8788) and `web` (5173) for development, `preview` (8788) for the production build.

## Rules

Details and the remaining rules are in the nested `AGENTS.md` files.

- **Every change updates both languages, Romanian and English.** Romanian is the default; English is chosen with the RO/EN button and kept in `localStorage` (`quickeval.lang`; `public/lang.js` puts it in `<html lang>` before the page loads, or sends a public page to its twin). A new text, page or feature is not done until its English is in too:
  - The apps: every text a page shows goes through `t()` (`src/i18n/t.ts`), keyed by its Romanian text, with `{name}` for values; its English goes in `src/i18n/en/` (one file per area). `t()` takes only keys the English dictionary has, so a missing English fails `npm run typecheck`. Counts go through `countLabel` / `tc`, dates and numbers through `locale()`. A string the page never shows, or one in one language on purpose (the robot's text), is marked `// i18n-ignore` (or `i18n-ignore-file`). `scripts/i18n/scan.test.ts` fails on visible text that skips `t()`.
  - The API, the emails and the shared code keep their Romanian text; its English is in `shared/i18n/messages.ts` (`{}` for a value). The API answers in English when the page sends `X-MQ-Lang: en` (`server/i18n.ts`: `localMessage`, `localEmail`). `scripts/i18n/messages.test.ts` fails on a Romanian message of `server/` or `shared/` with no English.
  - The public pages: each has its English copy under `en/` (`/en/`, `/en/guide/`, …), with `hreflang` both ways, its own canonical, share card (`public/en/og-*.png`) and pictures (`public/screens/en/`, the app in English on sample data with English names), and the footer `site-foot-en`. `src/landing/english.test.ts` fails when a copy drifts from its Romanian page (anchors, parts, pictures) or keeps Romanian text.
  - Screenshots: a new or changed app screen on a public page is shot in both languages; the English one uses English names. The robot's own text (feedback, the class analysis, a generated barem) stays in the language the robot writes.
- The API reports errors as `{ error, message }`; the UI shows `message`.
- Every address is English, because MQGrader will serve teachers outside Romania and an address is hard to change once people keep it: page paths, API paths, query parameters and their values, `#` anchors and `id`s that a link names. Only the text people read is Romanian (and English). "Barem" is `marking-scheme` in an address. A renamed address keeps its old form working (a 301 in `public/_redirects`, a router redirect, or an alias), and an address printed on paper (a QR code) works for ever. The plan for the addresses that are still Romanian: `docs/superpowers/plans/2026-11-17-english-addresses.md`.
- No page tells students that AI grades their work. Student-app tests check every screen with `expectNoGradingWords()`. Student pages show the site's header lockup ("MQGrader" with "by Laura Miron"), a "Despre" link to https://mqgrader.ro/about/ and the theme button; the mark and name link to https://mqgrader.ro/. The result page's footer has one link, "mqgrader.ro". No other brand text, no invitation to teachers, and no word on the page that says how the work is graded.
- Teachers log in with email and password (`server/routes/auth.ts`, a `qe_session` cookie). Setări and `/api/admin/settings` and `/api/admin/accounts` are for administrators only (`adminOnly` in `server/auth/teacherAuth.ts`). A new account confirms its email, then is pending and demo. The grading counters, the demo limits and when the class analysis is asked for are in `server/AGENTS.md`.
- Every teacher query is scoped by the teacher's id. Ids from URLs go through `parseId`, test codes through `parseTestCode`.
- Student and robot writes, and the teacher's corrections, check their own rules inside their SQL statement (`server/db/links.ts`, `server/db/runner.ts`, `server/db/evaluations.ts`), never in a check before the write.
- Every `/api/admin` and `/api/u` request first runs the `promoteDue` middleware. A router added under them keeps it.
- Quick Try (`docs/superpowers/specs/2026-11-09-quick-try-design.md`): one free grading without an account, at `/api/try`, with its private page `/try/<token>` (`src/try/`, noindex, closed in `robots.txt`). Its rules (guest teacher, allow-list, limits, cleanup, phone photos) are in `server/AGENTS.md`.
- R2 is private: every file goes through the API with an ownership check. R2 keys come from rows, never from listing R2.
- Functions: at most 10 ms of CPU and 15 D1 queries per request. Group writes with `db.batch()`.
- D1's free plan reads at most 5 million rows a day, for the whole account; past it every query fails until 00:00 UTC. A page that reads again on a timer multiplies its query by every hour it stays open, so the teacher pages read no data on a timer: the shell asks `GET /api/admin/version` every minute (`useDataVersion` in `src/admin/shell/refresh.ts`; two rows) and reads the shown pages again only when it changed. The version is `teacher_versions.version` (migration 0032), which triggers raise on every change of a test, an upload, its files, a grading or its points: a new table whose rows a teacher page shows needs its triggers there too. Count a table once per test, not once per number (`SELECT_TEST` in `server/db/tests.ts`; `server/db/testsCost.test.ts` holds its ceiling). `npx wrangler d1 insights quickeval --timePeriod 1d --sort-by reads --sort-type sum` lists the queries that read the most.
- The robot's Claude reads only its work folder and gets no robot key and no API key. Robot answers and logs carry no names.
- Every robot job counts in `usage_days` (Setări, "Statistici"; details in `server/AGENTS.md`). A new kind of robot work gets its column there too.
- The PDFs are made in the browser (`src/admin/pdf/`). The class CSV (`shared/csv.ts`) has no button now; it stays for when the teachers need it. The student's PDF is made from `StudentPdfInput`, which has no confidence and no review reason; the CSV guards every text cell against formulas.
- A generated barem ("Generează baremul", a robot job) is unchecked until the teacher confirms it; `BAREM_ACTIVE` (`server/db/lifecycle.ts`) keeps an unchecked or generating barem out of every evaluation start, and the robot waits for it too (`CLASS_BAREM_SETTLED` in `server/db/runner.ts`). A barem can be generated whenever its file can be replaced, at most `BAREM_GENERATIONS_PER_DAY` a day per account (`shared/accounts.ts`; administrators and Quick Try have no such limit). A barem the teacher uploads is always active.
- The CES variant (`docs/superpowers/specs/2026-11-09-ces-variant-design.md`): an adapted test with its own barem for students marked CES; details in `server/AGENTS.md`. No student page, student PDF, robot text for the student or CSV says "CES".
- Every path that makes work for the robot starts it (`startRobot`): the GitHub schedule does not fire. This includes "Regenerează" (the class analysis).
- A test gets its upload link (`upload_token`) when it is made, so the teacher prints the test with its QR code from the draft. Start, Stop and "Închide încărcarea" are in `server/AGENTS.md`.
- A print job is a draft or open test with its upload link, a test file and no print PDF (`NEEDS_PRINT`); every path that makes one starts the robot.
- Times are stored as ISO 8601 UTC strings (`nowIso()` or `new Date(x).toISOString()`: SQL compares them as text) and shown in Europe/Bucharest time. School year Y runs from September of Y to August of Y+1.
- Relative imports name the `.ts` or `.tsx` file. TypeScript runs with `erasableSyntaxOnly`: no enums, no namespaces, no constructor parameter properties.
- A new migration runs on the live database before the code that needs it reaches `main` (`docs/deploy.md`).
- Commits have no AI attribution lines. Code comments name no ticket or issue numbers.

## Gotchas

- npm blocks install scripts. After a fresh install, run `npm approve-scripts workerd esbuild`.
- Development happens on Windows. CI runs on Linux.
- On Windows, stopping a background `npm run preview` or `npm run dev:api` job can leave `workerd.exe` listening on its port. A new server then seems to start but answers with old data, or requests hang. Check with `netstat -ano | findstr :8788` and end the leftovers in PowerShell:

  ```powershell
  Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*\Projects\QuickEval\node_modules*' -or $_.CommandLine -like '*npm-cli.js*run preview*' -or $_.CommandLine -like '*npm-cli.js*run dev:*' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
  ```
